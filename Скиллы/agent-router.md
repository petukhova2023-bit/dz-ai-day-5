# agent-router

Скилл маршрутизации задач между специализированными агентами. Замена для постоянного «у нас 26 агентов, кто это делает?».

## Когда использовать

- Алекс получает задачу от владельца системы
- Не очевидно кто из агентов должен исполнять
- Задача затрагивает несколько направлений
- Нужно решить через одного агента или несколько параллельно

## Логика маршрутизации

### Основная таблица решений

| Ключевые слова в задаче | Агент |
|------------------------|-------|
| продажи, CRM, конверсия, дожим, менеджеры B2B | **Тим** |
| деньги, дебиторка, cash flow, валовая прибыль, P&L | **Света** |
| контент, посты, соцсети, выступление, презентация, бренд | **Софья** |
| бутик, ассортимент, маркетплейсы, e-commerce | **Наташа** |
| тендер, площадка, заявка, госзаказ | **Мира** |
| найм, кандидат, вакансия, резюме, продажник | **Оля** |
| дедлайн, контроль, исполнение, задача, срок | **Никита** |
| стратегия, координация, общая картина, неясно | **Алекс сам** |

### Многоагентные задачи

Если задача затрагивает несколько зон:
1. Определить главного исполнителя (owner)
2. Определить кто даёт вход (input)
3. Определить кто получает выход (consumer)

Пример: «Подготовить план найма продажника»
- Owner: **Оля** (HR-процесс)
- Input: **Тим** (требования к кандидату), **Света** (бюджет)
- Consumer: **владелец системы** (финальное решение)

### Эскалация к владельцу системы (без агентов)

- Критичный cash flow риск
- Крупная просроченная дебиторка
- Потеря ключевого клиента
- Стратегические решения по новым направлениям

## Output формат

```
ЗАДАЧА: <короткое описание>
ОВНЕР: <имя агента>
ВХОД ОТ: <если есть>
ПОТРЕБИТЕЛЬ: <кому результат>
ETA: <ожидаемый срок>
ПРИОРИТЕТ: P0/P1/P2/P3
```

## Антипаттерны

- Не передавать задачу нескольким агентам одновременно если можно одному
- Не маршрутизировать задачу которую может решить сам Алекс (стратегия, общая картина)
- Не пропускать эскалацию к владельцу системы для критичных решений
